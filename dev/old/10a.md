You basically have **one operation**:

* “Someone is asking me to save” → `requestSave({ force: bool })`

And two facts about the world:

* `dirty` – “there are unsaved changes”
* `moratoriumActive` – “I’m currently in a cooldown window”

Plus a timer that, when it fires, just makes the **same kind of ask**: a non-forced `requestSave(false)`.

So you get exactly what you want: **no special paths**. The timer is just another caller.

---

## State machine view

Let’s define:

* `requestSave(force = false)` – the *only* entry point.
* `dirty: boolean`
* `moratoriumActive: boolean`
* `moratoriumTimer: handle | null`

### External callers

Any time you detect “we should save now” (because some part of the system changed), you call:

```text
requestSave(false)
```

Any time you hit a “must save right now” situation (shutdown, explicit flush, whatever):

```text
requestSave(true)
```

### Timer

When the moratorium expires, the callback **also** just does:

```text
onMoratoriumEnd():
    moratoriumActive = false
    moratoriumTimer = null

    // If we were dirty, this is equivalent to a fresh request to save
    if dirty:
        requestSave(false)
```

That’s the clever bit you described: the timer is just another “ask”.

## Pseudo-code for `requestSave`

Here’s the minimal logic that matches your description:

```pseudo
dirty = false
moratoriumActive = false
moratoriumTimer = null

MORATORIUM_MS = 60_000


function requestSave(force = false):
    if force:
        // Force = "tell", not "ask"
        performSave()
        dirty = false
        startMoratorium()
        return

    // Non-forced = "ask"
    dirty = true

    if moratoriumActive:
        // Can't save yet; the timer will come back later and call requestSave(false) again
        return

    // Not in moratorium, so we are allowed to save now
    performSave()
    dirty = false
    startMoratorium()


function startMoratorium():
    moratoriumActive = true

    if moratoriumTimer != null:
        cancelTimer(moratoriumTimer)

    moratoriumTimer = setTimer(MORATORIUM_MS, onMoratoriumEnd)


function onMoratoriumEnd():
    moratoriumActive = false
    moratoriumTimer = null

    if dirty:
        // Same as any other non-forced save request
        requestSave(false)
```

That’s it. The behavior emerges entirely from the flags:

* **No separate “edge case” branch for the timer.**
* No need for last-save timestamps.
* No history beyond `dirty` / `moratoriumActive`.

Your “tell vs ask” intuition is exactly right:

* **Force** (`force = true`) = “tell” → save *now* and restart moratorium.
* **Non-force** (`force = false`) = “ask” → either save now (if allowed) or mark dirty and wait.
  The timer ending is just another “ask” that reuses the same logic.
